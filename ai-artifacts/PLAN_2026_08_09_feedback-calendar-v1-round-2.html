The 401, diagnosed

Feedback line 10 was two independent defects producing one symptom.

defect A — nobody exists npm run dev → docker compose up → ng serve never seeds a user npm run db:seed → migrator database seed audit marker, placeholder League, demo Live — no users POST /api/auth/login → FindByEmailAsync() is null → 401 invalid_credentials defect B — the cookie is thrown away compose.yaml api: ASPNETCORE_ENVIRONMENT=Production appsettings.Development.json never loaded RefreshCookieOptions.Secure defaults true browser over plain http:// refuses a Secure cookie gones_refresh never stored next reload → POST /api/auth/refresh → 401
Fix both or fix nothing. Seeding alone gives a login that silently signs you out on every reload. T1 does both and its unit test guards the release compose files against inheriting the insecure default.

The League slice

Feedback line 4 asked for the League Archive to "work exactly like the live tournament feature" — and then, one sentence later, for something that shape cannot do.

Live Tournament (ADR 0021)League Archive (ADR 0028)
AdaptersTwo, exclusiveTwo, merged
Chosen byRole, once, at injectionThe league's id, per call
An Organizer seesServer onlyServer and local, badged
Export reachesThe bound adapterBoth stores
SyncNeverNever

Exclusive adapters mean a signed-in repository has no handle on the browser store, so "export all leagues" cannot see what was made signed out. Those leagues would go missing the first time somebody exported and cleared their browser. Hence: merge on read, route on write.

origin lives in the id — that is the whole routing layer local-9f2c1a7e-… browser-local league local-placeholder-league browser-local "Unassigned" bucket placeholder-league the server's fixed bucket 7f3a… server league listLeagues() → allSettled([server, local]) → concat server fails → local only, flagged getLeague(id) → isLocalLeagueId(id) ? local : server createLeague(name) → createLeagueTarget(role) the one call with no id to route on canManageLeague() → isLocalLeagueId(id) || role is Organizer/Admin
Parity is a compiler check. LocalLeagueArchiveBackend implements LeagueArchiveBackendPort, all 22 methods, no Partial. Add a capability to the port and implement it server-only → npm run typecheck fails. No feature can quietly become signed-in-only.

The one conflict, and how it resolved

Line 6 wanted the fuzzy filter to add and remove events on the calendar. Line 9 wanted the tournament entries gone from the calendar. Both cannot hold. Raised, and the user reconfirmed:

calendar tab, after T10 ┌─────┬─────┬─────┐ │ 1 │ 2 │ 3 │ day numbers only — no pills, no titles, no links ├─────┼─────┼─────┤ │ 8 │ 9 │ 10 │ └─────┴─────┴─────┘ filter still drives → items() → empty-state panel calendar tab → groups() → cards list tab

Consequence, accepted: the search box has no per-event effect on the calendar tab. Tournament discovery lives on the List tab. buildMonthDays(month) stops depending on the filtered set, so typing no longer re-renders the grid.

How to execute

  1. Read the ticket file. It is self-contained by design — it quotes what its predecessor produced, so you never need the index or a sibling ticket.
  2. Read the ADR named in its Context section first, if it names one. It is the specification, not a summary.
  3. TDD: write the failing test, run it, watch it fail, then implement.
  4. Walk the Validation checklist. Every box, including the manual ones.
  5. Commit with the drafted message. One ticket, one commit, app functional after each.
