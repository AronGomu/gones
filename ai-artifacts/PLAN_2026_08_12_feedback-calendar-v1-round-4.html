Feedback Calendar V1 — Round 4

19 feedback items, 19 commit-sized tickets, in three blocks: calendar and event-detail polish first, then the admin organization workbench with a derived Organizer role, then the full Tournament → Event rename as the closing sweep. The app compiles and runs after every ticket.

Goal

Ship every item of feedback.md: calendar page polish, event detail reflow, a single admin screen for the many-to-many organization ↔ organizer graph, a session-ready fix for guarded routes, generated demo-account documentation, and the calendar-domain rename across database, API, frontend and routes.

in scope Shipping

  • Calendar page: past-day dimming, clickable cards, hover, local time, search highlighting, scroll anchor
  • Event detail: title row, when/where row, maps link, action row, success dialog
  • Admin: organization workbench, derived Organizer role, Draft organizations, all-orgs picker
  • Auth: session-ready guards
  • Docs: generated DEMO_ACCOUNTS.md, ADRs 0033-0035
  • Rename: Event entities, /api/events/*, /events/:slug

out of scope Deferred

  • Event as a container of several tournaments
  • Server-side paginated user search (until the 500 cap trips)
  • Cancellation and notification flows for deleted organizations
  • Renaming tournament_formats, the league archive, the live domain

Three blocks, one chain

T1 ─ auth guard fix — the reported /registrations bug and the whole race class
T2 … T9 ─ polish — calendar view, list view, detail page, demo docs
T10 … T14 ─ organizations — read model, derived role, heal migration, workbench, picker
T15 … T18 ─ rename — entities and tables, API, frontend symbols, routes
T19 ─ documentation, ADR status, acceptance matrix
Why the rename is last. It touches every file the polish tickets touch. Renaming once at the end beats rebasing eighteen tickets across a mechanical diff.

Assumptions

  • Draft is derived from the member count, never stored.
  • Past calendar day = venue date strictly before today; today is never dimmed.
  • Highlighting marks literal substring matches inside fuzzy-matched cards.
  • Every rendered element carries data-cy; every i18n key exists in both the en and fr maps.
  • The frontend is knowingly mid-rename between T16 and T17; those commits stay adjacent.
Riskiest ticket: T15. EF scaffolds a drop-and-recreate for an entity rename. The migration must be hand-corrected into rename operations or every event row is lost. The gate is grep -n "DropTable\|CreateTable" on the new migration printing nothing.
