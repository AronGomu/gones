Facts scouted from the repo — not up for debate, they constrain the answers

  • A match is MatchRoundEntry: two names, two integer scores (games won), two archetypes. Draws are representable and counted (matchDraws). Byes are a separate entry kind.
  • A player is a trimmed name string. No account, no id, no rating field anywhere today.
  • The only time signal is tournament.tournamentDate (a date, no clock) plus the round's array index. Matches inside a round have no order.
  • ADR 0040 already materializes player_statistics, rebuilt fully and synchronously in the same transaction as every archive write, keyed by PlayerStatisticsFormula.Version. 100× dataset rebuild = 1183 rows from 201 leagues in 177 ms.
  • ADR 0040 scope: only tournaments with status === 'completed' feed global statistics.
  • ADR 0028: browser-local leagues (local- id prefix) never reach the server, so the server read model cannot see them. The player page merges them client-side behind an Online only toggle.
  • Existing standings (results.ts) are Swiss: 3/1/0 points, bye = free win worth 3, tiebreaks OMW% and OGW%. Global stats currently sort by name, then matchWins.
1. What does one rating update consume — the match result, or the game score inside it?

A match carries two integer game scores, so 2–0 and 2–1 are distinguishable; deciding now fixes whether dominance is signal or noise.

2. Which rating algorithm family?

The family decides whether the rating can express uncertainty, whether it is order-dependent, and how much maths lands in the domain layer.

3. How are matches ordered in time, given only a tournament date and a round index exist?

Every sequential rating is order-dependent, and today two tournaments on the same date have no defined order — an arbitrary choice would make the number silently unstable.

4. Is a league rating the same number, or a separate rating computed over that league only?

The goal names two uses — a global ranking across all leagues and a ranking inside a league — and they need not be the same computation.

5. How do byes and draws affect the rating?

The archive already treats a bye as a 3-point free win, and draws are first-class — a rating has no opponent for the first and no winner for the second.

6. When does a player become rankable — is there a minimum activity gate?

Without a gate, one lucky 2–0 in a first tournament can top a global leaderboard, and the metric loses credibility on day one.

7. Which archive data feeds the rating?

ADR 0040 already restricted global statistics to tournaments marked completed; the rating can inherit that rule or diverge from it.

8. What happens to browser-local league archives, which the server can never see?

ADR 0028 keeps local- leagues strictly in IndexedDB, so any server-computed rating structurally excludes them — the player page already merges local data client-side behind an Online only toggle.

9. How is the rating stored and recomputed?

A rating is order-dependent state, unlike every existing statistic — an edit to a two-year-old tournament changes every later rating, so incremental updates are not safe by default.

10. Does the rating become the default sort, and what happens to the metrics it displaces?

The goal calls this "the default metric", which means changing what the rankings page shows first and possibly what a league standings table is ordered by.

11. Does inactivity change the rating?

The archive spans years; without a rule, a player who stopped playing in 2023 can hold the top spot forever against people still competing.

12. What does a player actually see — a raw number, a tier, or a movement?

Presentation decides how much of the maths must be explained, and whether a confidence value ever reaches the screen.
