1. The private store — extend, sibling, or localStorage

You chose a user-scoped store purged at logout. That describes ServerReadCacheService — except its ADR 0031 contract is fallback-only: a row is read only when the server read has already failed. Making it serve fresh navigations is a change to what that cache means.

2. Catalog cache vs per-query cache

Calendar caches everything from /api/events/all and does search, sort and paging in the browser — that is why it feels instant. Global Rankings, Leagues Archive, admin Users/Organizations/Audit and Registrations are all server-paged with page/size/search/sort, so "cache like Calendar" has two possible meanings.

3. Read-model scope — completed only, or everything played

The two readers disagree today: Global Rankings counts completed leagues only, the player page counts all leagues. One table means one answer, so one of the two surfaces changes behaviour whatever we pick.

4. Browser-local leagues in player stats

ADR 0028 lets a Power User keep League Archives that live only in this browser's IndexedDB and never reach the server. The player page counts them today, and the Online only checkbox (gones.playerStats.onlineOnly) exists precisely to filter them out. A server-computed table cannot know they exist.

5. Rebuild timing

Archives change a few times a week, but a full recompute at 100× reads every league document. Doing that inside the request that commits an archive edit makes that request slow; doing it later means a window where the table is behind the archive.

6. Stress seeding — the bulk boundary

You chose accounts and organizations through the API, leagues and events bulk-inserted. That leaves three populations unassigned, and one of them is expensive: Live tournaments are seeded today by replaying real commands (create → add players → start → score → validate each round). Two hundred of those is a long replay.
