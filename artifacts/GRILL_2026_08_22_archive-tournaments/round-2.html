1. Do attached Tournaments move out of the League document too?

Q1-A said "new top-level aggregate" but not whether it holds every Tournament or only the orphans. This single answer decides the migration size, the number of write paths, and whether the Tournaments tab queries one source or unions two.

2. How is a Tournament identified?

A Tournament row on its own tab needs a stable, linkable identity. Today ids are only unique within a League document, and imported bundles can carry colliding ones — a flat route would then be ambiguous.

3. API routes and response schema for the Tournament catalog

You chose the full rename with an alias, so the new namespace has to be named exactly once, here. This is the contract every ticket will quote verbatim.

4. Canonical UI route for a Tournament

A Tournament reachable from both tabs needs one canonical URL, or the same page gets two addresses and the breadcrumb cannot decide what it is under.

5. What is the Tournament catalog cap?

"Fetch everything on the first request" needs a ceiling, because 1000 Leagues × up to 1000 Tournaments is a 10⁶-row worst case against a ~5 MB localStorage quota — the exact pressure ADR 0042 was written to remove.

6. Do standalone Tournaments feed ratings and Global Rankings?

ADR 0043 replays "every completed Archive Tournament in date order" into Glicko-2. Today every one of those sits in a League, so the rebuild walks Leagues. Standalone Tournaments either join that walk or silently do not count.

7. Export bundle and GONES_DATA_VERSION

Gones Export / Restore is the backup path, and GonesData currently has exactly two collections — leagues and calendarEvents. Standalone Tournaments have nowhere to go in a v4 bundle.

8. Power-user create and move semantics

The repository already has moveTournament(tournamentId, fromLeagueId, toLeagueId). A nullable League makes "move to no League" a new, reachable state, and "create a standalone Tournament" needs a home in the UI.

9. What does an expanded League row render?

The expanded child rows are a new surface with no precedent in the codebase, and "all related tournaments" does not say which columns or how many.

10. Column order, sortable set, default sort, URL state

Your six columns need one fixed order and one default sort, or the two tabs and the prototype variants will each pick differently. Level 5 cannot leave this to the implementer.

11. Should cache-invalidation coverage be enforced by a test?

This is the residual risk from your Q7 verification. The wiring works today, but nothing proves it stays working, and this rebuild doubles the number of cache keys every mutation must clear.
