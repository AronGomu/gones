Scope check — read this before answering

Rounds 1–2 already committed a large plan: a new Tournament aggregate, every Tournament lifted out of the League document, a full leagues-archive → archive rename with API aliases, a data migration, a v5 export format with v1–v3 dropped, a six-column two-tab table refont, and centralized cache invalidation. Q6 adds a third entity tier and a scoped ranking read model on top of that. Question 1 is whether that all ships as one plan or as two — everything else in this round is worth answering either way, because a phase-2 plan still needs the contracts frozen now so phase 1 does not paint them into a corner.

Facts resolved for this round — do not re-answer

  • Every archive command is versioned against the League today. All ~15 signatures in application-backend.ts:76-96 take the League's expectedVersion and return a PersistedLeague — e.g. addArchiveRound(id, tournamentId, expectedVersion). Q1-B makes the Tournament its own row, so every one of these changes shape. Q10 settles how.
  • ADR 0037's edit-batch is explicitly League-versioned. Source If-Match is mandatory, Target-If-Match accompanies a move, and the server "locks source/target rows in deterministic League-id order". A Tournament with its own version changes what is locked and what 412s.
  • ADR 0043 replays every completed Archive Tournament in date order to derive one Glicko-2 rating per player, materialized by ADR 0040 into player_statistics — a table with one row per player. A per-League ranking has no place to live in that shape. Q7 is where that is decided.
  • Rating fields on that read model: rating, ratingDeviation, previousRating, tournamentsPlayed, lastPlayedDate, plus the derived provisional (<5 tournaments) and inactive (no completed tournament in 12 months) flags.
  • Global Rankings already ships a search box, a sortable header, a 10/25/50/100 page-size selector and query-string state — the filter controls in Q8 join an existing control row, they do not create one.
  • docs/CONTEXT.md is the language contract and docs/GLOSSARY.md the shared vocabulary; both define "League" with today's meaning. Q3 decides how much of that vocabulary is rewritten.
1. Does the whole hierarchy ship in this plan, or is it phased?

Rounds 1–2 are already a big plan. The League-group tier and the scoped ranking are a second feature riding along. This decides how many tickets I write now — but I will freeze every contract either way, so a phase 2 is never blocked by phase 1's shape.

2. Must every Season belong to a League?

Exactly the question Q1 answered for Tournaments, one tier up. If the parent is optional the model is uniform — every tier has a nullable parent — and a one-off season needs no ceremony.

3. Naming — reuse "League" for the group, or a new word?

You said the group is called "League" and today's League becomes "League Season". That redefines a word used across docs/CONTEXT.md, the glossary, ~20 API routes, every component name and every test — on top of the leagues-archive → archive rename already agreed. There is a cheaper way to get the same hierarchy.

4. What do the Archive tabs list now?

Round 1 settled two tabs over a two-tier model. A third tier has to appear somewhere, and it changes what column 4 counts and what a row expands into.

5. Does a Tournament point at a Season or at a League?

Q3 of round 2 froze the Tournament catalog row as carrying leagueId and nothing else. With three tiers that field needs a target, and column 4 of the Tournaments tab needs to know which name it prints.

6. What does the migration do with today's Leagues?

Every existing League becomes a Season. Whether each also gets a wrapper League decides what the Leagues tab shows the morning after the migration, and whether the ranking filter has anything in its dropdown.

7. Scoped ranking — recomputed rating, or filtered view?

The single most consequential question in this round. ADR 0040's player_statistics holds one row per player and ADR 0043 derives that rating by replaying every completed Tournament in date order. "Ranking for a specific league" can mean two very different things, and one of them multiplies that table.

8. Ranking filter — UI contract, defaults, URL state

You described a League select that reveals a season multi-select. Level 5 needs the default state, the empty-selection meaning and the query-string shape written down, or three implementers build three behaviours.

9. UI and API routes for the two league tiers

Round 2 froze /archive/tournaments/:id and /api/archive/tournaments/all. The two tiers above need the same treatment, named once, here.

10. What does optimistic concurrency guard now?

Q1-B broke a contract nobody has replaced yet. Today every archive command takes the League's expectedVersion and returns a PersistedLeague; ADR 0037's edit-batch sends a mandatory source If-Match and locks League rows. With Tournaments as their own rows, all ~15 signatures change shape.

11. The v5 export bundle with three tiers

Round 2 settled v5 with v1–v3 dropped, but the shape it settled had two tiers. Backup and restore is the one path where getting the shape wrong loses data, so it gets stated explicitly.
