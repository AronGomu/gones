Archive table — three variants

Same data, same six columns, same behaviour contract — three different treatments of the League Seasons tab, plus the filtered Global Rankings. Real theme tokens from src/styles.css, not an approximation. Click any row to expand it.

What is identical across all three — column order Name · Last played · Updated · #Tournaments · Players · Status; default sort Last played descending; the Name cell is the link and the rest of the row toggles expansion; expanded children are one continuous clickable line; year selector; search; query-string state. What differs — density, how the numbers are grouped, and how much the row separates from its neighbours.

Variant A — Dense grid

The Global Rankings table, reused. Tight rows, hard column alignment, zebra striping. Maximum rows per screen; the most "data tool" of the three.

Global Rankings — scoped filter

League select and Season select are each All or exactly one, so every selectable scope has a stored Glicko-2 rating. Positions renumber 1..n within the scope. The badge states which scope the rating was computed in, so a scoped number is never mistaken for the global one.

every shown rating actually computedno on-demand replay scope stated, never impliedcannot combine arbitrary seasons
