Live Tournament Authority

Live Tournament has two data authorities. Which one you get depends on your role, and the two never talk to each other. Everything else in Gones still has exactly one.

Synchronisation is the privilege. Being able to put a Live Tournament on the server is what Organizer means. See ADR 0021.

Where the decision is made

// src/app/backend/application-backend.ts

export type LiveBackendMode = 'aspnet-api' | 'browser-local';

export function resolveLiveBackendMode(
  authority: DataAuthority,
  globalRole: string | undefined
): LiveBackendMode {
  if (!authority.serverAuthority) throw new Error('serverAuthorityRequired');
  return globalRole === 'Organizer' || globalRole === 'Admin'
    ? 'aspnet-api'
    : 'browser-local';
}

export const LIVE_BACKEND = new InjectionToken<LiveBackendPort>('Gones Live Tournament backend bridge', {
  providedIn: 'root',
  factory: () => {
    const role = inject(AuthService).profile()?.globalRole;
    return resolveLiveBackendMode(dataAuthority(), role) === 'aspnet-api'
      ? inject(AspNetApiBackend)
      : inject(LocalLiveBackend);
  }
});
Resolved once. The profile is loaded by AuthService.bootstrap() in a provideAppInitializer, before the first route renders. A role granted mid-session takes effect on the next reload. That is a deliberate simplification, not an oversight.

What did not move

  • Leagues. LEAGUE_ARCHIVE_BACKEND binds to the API and nothing else.
  • Calendar, auth, organizer, admin. Server-authoritative, per ADR 0020.
  • The domain rules. Pairing, standings, checkpoints and finalize live in one pure module that both adapters compose. Neither adapter reimplements a rule.

Guardrails in the test suite

server-authority-boundary.test.ts is the enforcement point. It asserts, by exact file list, that indexedDB appears only in src/app/backend/indexed-db.ts and src/app/backend/local-live-backend.service.ts; that localStorage stays inside its documented allowlist; that the retired local-frontend-backend.service name is never imported; and that the retired browser-store keys are never named. Adding a browser-storage caller anywhere else fails the build until it is justified in that file.

Accepted costs

  • A local tournament lives in one browser profile. Clearing site data destroys it.
  • No cross-device recovery, no organizer rescue of a plain user's tournament.
  • No migration in either direction — a plain user's server-side Live tournaments are not pulled down, and local ones are never pushed up.
