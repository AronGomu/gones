## Invariants

I1. PostgreSQL owns work. Wake hints contain no job payload. Commit precedes hint; full tx rollback/disposal emits none. Manual savepoint rollback may retain conservative payload-free hint after successful outer commit; DB requery exposes no rolled-back work. Signal loss never fails committed business mutation. Immediate target ≤5s plus DB cold-start. Missed-wake recovery ≤1h while process healthy; rollout conditional on measured total-cost savings versus equivalent always-awake DB.

I2. Due timers never authorize delivery. Requery/claim committed rows on wake; preserve notification dedupe, leases, provider uncertainty, image retry state, 60s reminder expiry. Earlier hints survive final-query/sleep race. Startup already reconciles via first polling pass; redesign retains this, not invents absent recovery.

I3. Known-idle Worker owns no DB scope, connection, transaction, advisory lock. Local health distinguishes idle, busy/progress, failed, stopped. Explicit deep readiness retains DB/outbox/S3 failures. No background readiness scraping.

## Producer / transaction matrix

All paths below are under `backend/src/`. HTTP wake integration must cover entity mutations centrally, not only calls to `INotificationOutbox.Enqueue`. Implicit `SaveChanges` must signal only after successful save; explicit tx must signal only after outer commit, including multiple saves. Full tx rollback/disposal discard pending hint. Failed save discards only that save candidate; earlier successful tx writes retain hint. EF savepoint callbacks omit names: conservative hint after successful outer commit may survive manual savepoint rollback, costing one unnecessary wake but authorizing no phantom job. Worker DB registrations omit producer signaling → no self-trigger loops.
