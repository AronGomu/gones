# Rebuild the Archive Without a Migration

## Status

Accepted. Not yet implemented. Amends ADR 0020 (retire the legacy browser data authority) by closing
the import door it left open, and amends ADR 0022 (rename the archived League feature) by unfreezing
the export wire names it deliberately froze. Carries out ADR 0045's three-tier shapes; the lock rule
it ships alongside is ADR 0046.

## Context

ADR 0045 turns one archive row per League, holding every Tournament inside a single jsonb document,
into three tables with one row per Tournament and no embedded array. Nothing in the existing data
answers the questions the new shape asks. There is no League tier to lift the old Leagues under, no
Season name for any of them, and `TournamentDocument.leagueId` at `src/app/domain/models.ts:69`
points at a tier that is about to mean something else. Any migration would have to invent the
missing facts.

It would also be inventing them for nobody. **Gones is unreleased: there is no production
environment and there are no users.** Every archive row that exists is developer fixture data,
regenerated by `npm run db:reset` and `npm run dev:env`. A migration would be careful work to preserve
data whose canonical source is a seed script.

The second half of the problem is the EF migration history.
`backend/src/Gones.Infrastructure/Persistence/Migrations/` holds 71 files — 35 migrations, their
designer files, and the model snapshot. Four of those migrations exist only to build, rename and
extend the very tables this rebuild deletes: `20260802204547_AddLeagueAggregates`,
`20260809122735_RenameLeagueArchiveTables`, `20260816132203_AddArchiveTournamentStatus` and
`20260820113606_AddLeagueArchiveCatalogCounts`. Replaying a table into existence in order to drop it
later is dead weight in a repository where no environment has ever been upgraded in place.

Two alternatives were weighed and rejected.

- **Write the migration anyway, lifting every existing League to a Season under one synthetic
  "Default" League.** Rejected: it produces a League nobody chose, named by the migration rather than
  by a person, and it would be the `placeholder-league` mistake wearing a new tier. The only data it
  preserves is fixture data.
- **Keep all 35 migrations and add the three tables on top.** Rejected: the history would then
  describe a schema that no revision of this repository ever wants again, and every future
  `dotnet ef migrations add` would carry it. There is no environment whose `__EFMigrationsHistory`
  has to be respected, which is exactly the condition under which a squash is safe — and that
  condition will not be true again after the first release.

## Decision

**Delete all archive data, rebuild it from scratch, and squash the history down to a baseline plus
one delta.** There is no upgrade path, and none will be written.

1. **No data migration and no dual-read.** The archive is emptied, the new tables are created, and
   the data comes back from the seed and stress fixtures in the new shape. This is defensible only
   because there is no production environment and no user data, and that justification expires with
   the first release. After that, ADR 0022's `RenameTable`-not-drop discipline applies again.

2. **Migration history is squashed from 71 files to two migrations: a baseline `InitialCreate` and a
   `RebuildArchiveThreeTier` delta.** The archive reset and the three-tier schema are separate
   commits, and each commit in this repository has to build, migrate and run on its own.
   Regenerating a single combined `InitialCreate` at the second commit would delete the baseline the
   first commit just created and emit a different one in its place: the tree passes through a state
   with no migration at all, and any database already stamped with the first `InitialCreate` in
   `__EFMigrationsHistory` can no longer be brought forward — `dotnet ef database update` has nothing
   to apply and no way to reconcile the row it finds. Every developer database and the CI database
   would have to be dropped in lockstep with that one commit. Two files is the price of not doing
   that, and it is cheap.

3. **The squash cannot be a pure model diff.** `dotnet ef migrations add` emits DDL from the model,
   and five artifacts in the current history are installed by raw SQL or `InsertData` and are
   therefore invisible to it. Each one is load-bearing for a named test that passes today, so each is
   carried into `InitialCreate` verbatim rather than regenerated:

   - **The append-only audit guard and its triggers.**
     `20260724112436_AppendOnlyAuditGuard.cs` creates `reject_audit_mutation()`, the
     `audit_records_append_only` row trigger, the `audit_records_no_truncate` statement trigger, and
     `REVOKE UPDATE, DELETE, TRUNCATE ON audit_records FROM PUBLIC`.
     `20260808164636_AllowAccountHardDelete.cs` then narrows the function so that exactly one change
     — an `UPDATE` that nulls `actor_id` and alters nothing else — is allowed through. Without them
     `PersistenceKernelTests.Audit_records_reject_ef_and_raw_sql_mutation`, which asserts SQLSTATE
     `55000` for a raw `UPDATE`, a raw `DELETE` and a `TRUNCATE`, and
     `AccountDeletionTests.Audit_records_stay_append_only_apart_from_the_actor_reference` both fail.
   - **The audit grant.** `20260808164636_AllowAccountHardDelete.cs:39-47` runs
     `GRANT UPDATE (actor_id) ON audit_records TO gones_app`, wrapped in a `pg_roles` existence check
     because that role is absent from throwaway test databases. It is the only write privilege the
     application role holds on an append-only table, and a hard account deletion cannot complete
     without it.
   - **The `tournament_formats` Legacy seed.** `20260801152724_AddAdminBootstrapAndFormats.cs:79-82`
     inserts the single row `('…f1', 'Legacy', 'legacy', 0, …)`.
     `AdminBootstrapAndCatalogTests.Public_formats_lists_seeded_legacy_only_active` asserts the first
     public format has slug `legacy` and name `Legacy`.
   - **The 49 `deck_archetypes` seeds.** `20260805105726_AddDeckArchetypeCatalog.cs` inserts 49 rows
     in one raw `INSERT`. The test
     `DeckArchetypeCatalogApiTests.Public_deck_archetypes_lists_seeded_legacy_presets`
     compares the response length against `DeckArchetypePresets.LegacyNames.Count` in
     `backend/src/Gones.Domain/Catalog/DeckArchetypePresets.cs`, which holds exactly 49 names.
   - **The fixed `placeholder-league` row.** `20260802204547_AddLeagueAggregates.cs:38-51` is an
     `InsertData` of document id `placeholder-league`, name `Unassigned Tournaments`, with its
     canonical document inline. The test
     `PublicLeagueCatalogApiTests.Returns_every_visible_League_as_a_summary_row`
     asserts it trails the catalog ordering, and `LiveCommandApiTests` looks it up by document id.

   This is recorded so that nobody regenerates the baseline from the model at some later date and
   quietly loses five things the model has never known about.

4. **`placeholder-league` therefore survives to the very last ticket of the rebuild, not the first.**
   The obvious sequencing — delete the placeholder in the reset that empties the archive — breaks the
   command the reset is validated with. `LeagueArchiveAggregate.SoftDelete` throws
   `Placeholder League cannot be deleted.`; `MigrationImportService` calls `SingleAsync` on the row at
   `backend/src/Gones.Infrastructure/MigrationImport/MigrationImportService.cs:138-139` and again at
   `:286-288`; and `scripts/seed-local.mjs:12-13` throws
   `Fixed placeholder League missing or duplicated.` when the row is absent, which fails
   `npm run db:reset` — the very command the reset ticket mandates. So the row is re-seeded by
   `InitialCreate` and dies with the rest of the legacy surface at the end, after the new archive is
   complete and nothing reads it. ADR 0045 retires the *construct*; this ADR fixes *when*.

5. **The export bundle goes to v5, four flat collections, and the import gate accepts only v5.**
   `ARCHIVE_DATA_VERSION = 5` and `SUPPORTED_ARCHIVE_IMPORT_VERSIONS = [5]`. The bundle is
   `{ version: 5, leagues, leagueSeasons, tournaments, calendarEvents }` — flat, with the parent
   links carried as `leagueId` on a Season and `seasonId` on a Tournament, mirroring the tables. A
   v1–v4 bundle is refused with a clear message; **no converter is written**.

6. **This closes ADR 0022's import door, on purpose.** ADR 0022 froze `kind: "league"`,
   `kind: "fullData"` and every JSON field name, and said why: "ADR 0020 left one door open — the
   import CLI applies bundles exported before it — and a wire-format rename would slam it." That door
   is now shut deliberately. ADR 0020 had already deleted the browser exporter that produced those
   bundles — "There is no longer any way to produce a migration bundle" — so the only v1 bundles that
   could ever be offered are files a developer keeps on disk, and the owner's data is already out as
   JSON. Keeping a reader alive for a format nothing can write, describing a schema that no longer
   exists, is not compatibility; it is a museum.

7. **A new golden set, not a replaced one.** `fixtures/archive-domain/v5/` is added as the
   export/import golden corpus for the new bundle. `fixtures/league-domain/v1/` is **not** deleted
   with it: despite its name it is the TypeScript↔C# domain-parity corpus, emitted by
   `src/app/domain/league-parity-fixtures.test.ts` and read back by
   `backend/tests/Gones.UnitTests/LeagueParityTests.cs:172` and
   `backend/tests/Gones.IntegrationTests/LeagueArchiveRouteTests.cs:183`. It is re-pointed at the new
   shapes when the legacy surface retires. Losing cross-stack parity proof was not an acceptable
   trade for a tidy fixtures directory.

## Consequences

- **Every existing archive row is destroyed, in every developer's database, with no recovery.** The
  seed and stress fixtures are the source of truth for what comes back, and they are rewritten to the
  three-tier shape in the same series. Anyone holding archive data they care about must export it
  before the reset — and the resulting v4 bundle will not import afterwards.
- **Any v1–v4 bundle still on disk becomes permanently unimportable** without reverting this work.
  That is the deliberate part of point 6, and it is the one consequence that cannot be undone later
  by writing more code, because the schema the old bundle describes stops existing.
- **`npm run migration:smoke` has to be re-pointed at v5.** `scripts/smoke-migration.mjs` builds its
  bundles in JavaScript and has the C# importer verify their canonical checksums, which makes a run
  of it the cross-stack canonical-hash parity proof as well as the CLI rehearsal. Both halves move to
  the new shapes together or the checksum comparison is meaningless.
- **The squashed history loses the record of how the schema got here.** Thirty-five migrations
  documented a year of decisions, and after the squash `git log` is the only place that story
  survives. That is an accepted trade, taken once, while there is no environment to upgrade. It is
  not repeatable after the first release.
- **The five carried-forward artifacts are now hand-maintained inside a generated file.** A future
  regeneration of `InitialCreate` will silently drop them unless whoever runs it reads this ADR
  first. The named tests in point 3 are the backstop: each one goes red, and each one names the thing
  that went missing.
- **Two migration files is a permanent shape, not a temporary one.** `RebuildArchiveThreeTier` is
  never folded into the baseline afterwards, for the same reason it could not be folded in at the
  time.
- **`placeholder-league` outliving most of the rebuild means the legacy tables outlive it too.** The
  old aggregate, its endpoints and the `league_archive_aggregates` table all stay queryable until the
  final retirement commit, and `backend/src/Gones.Api/Live/LiveCommandEndpoints.cs:358-364` — which
  validates a live tournament's `leagueId` against `LeagueArchiveAggregates` — has to be re-pointed
  at `archive_league_seasons` in that same commit or live seeding breaks.
