# Derived Results in Pure Domain Modules

Gones stores tournament source data such as Leagues, Tournaments, Rounds, Round Entries, imports, and exports, while Tournament Results, League Results, Player Statistics, warnings, and provisional state are derived. We decided derived calculations belong in pure domain modules outside page files, so pages save source data, call calculation functions, and render the returned views. Domain calculation functions must not mutate their inputs, and they return raw values such as numeric ratios, `null` for N/A, validation codes, or structured warning codes rather than UI-formatted strings. Validation and warnings are separate domain responsibilities: validation identifies invalid source data, while warnings identify usable but suspicious source data. Round Import parsing is also a pure domain adapter: it accepts pasted text plus dependencies such as an ID factory, then returns Round Entries and codes without touching DOM, files, storage, or the current Tournament. Gones Export and Restore are split the same way: domain functions handle versioned data shapes, validation, migration, and ID remapping, while browser file APIs and localStorage stay in page or storage code. UI code may manipulate source data as long as the domain data shape stays UI-agnostic. Display-specific shapes, validation text, warning text, and formatting belong in mapper functions that convert domain data or derived results into the format needed by a page or component, and those mappers should live near the UI that uses them rather than in a generic view-model layer. Ranking presentation should use a Ranking Table component rather than pretending the current table is a generic data table. This keeps DOM code from becoming the source of ranking truth and makes recalculation consistent after every edit, import, export, and restore.
