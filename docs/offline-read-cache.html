Gones · Architecture

Offline Read Cache

Four browser stores, one rule each. Two are authorities for their own documents, one is a public snapshot, and the fourth — new — is a per-user mirror of server responses that dies at logout. Remote always prevails; nothing local is ever uploaded.

The four stores

authority gones-live

IndexedDB. The Live Tournament store for anonymous visitors and the plain User role (ADR 0021). Chosen by role once at injection time. Never synchronises, in either direction. Browser-wide, not user-scoped.

authority gones-archive-local

IndexedDB. The browser half of the dual-source League Archive (ADR 0028). Merged with the server list, routed by the local- id prefix. Never synchronises. Browser-wide.

public gones.calendar-v1.all-tournaments

localStorage. A 24-hour snapshot of the public tournament catalog, anonymous GET responses only. Browser-wide, because it holds nothing private.

cache gones-cache

IndexedDB, new (ADR 0031). Server responses for a signed-in visitor, keyed <userId>:<resource>. Read-only, never an authority, purged on logout.

How a read resolves

anonymous → no cache at all · read() passes straight through to load()
signed in · load() fulfils → overwrite the row → { value, stale: false }
signed in · load() rejects · row exists → { value: row, stale: true } → banner
signed in · load() rejects · no row → rethrow the original error, no empty-state lie
any IndexedDB failure on write → logged and swallowed · a broken cache never breaks a good read
logout / failed bootstrap / account deletion → SessionScopeService.clear() → database dropped

"Remote prevails" — the two surfaces

1 · The cache row

A fulfilled server read replaces its row. There is no merge, no field-level reconciliation, no "keep the newer one". The cached copy exists to answer a failure, and stops existing the moment the server answers again.

2 · The deck archetype catalog

The one list that exists both in localStorage (gones.settings, ADR 0032) and on the server. On sign-in and on a successful bootstrap, adoptServerCatalog(names) replaces the browser list with GET /api/deck-archetypes. Local additions are erased. A failed fetch changes nothing, so signing in offline is safe.

Browser-local documents are outside this rule. A browser league carries a local- id and a browser running tournament lives in a role-selected store, so neither can collide with a server document. There is no conflict to resolve, and signing in does not erase them.

Why per-user, and why it dies at logout

The same browser is shared. SessionScopeService already purges the service worker's API response cache on logout for exactly this reason. A durable cache of user A's leagues that user B can read after switching accounts is a data leak, and no offline convenience is worth it.

So: rows are keyed by user id, and the whole database is dropped by the reset registered with SessionScopeService. Closing a tab keeps the cache — that is the case the feature exists for. Signing out does not.

Two properties, deliberately opposite. gones-live, gones-archive-local and gones.settings are browser-wide: anyone opening the site in that browser sees the same local data. gones-cache is the single user-scoped store. browser-local-scope.test.ts asserts both directions so the distinction cannot rot into an accident.

Boundary

server-authority-boundary.test.ts pins the exact set of files allowed to name IndexedDB. It is now four:

src/app/backend/indexed-db.ts                          promise wrapper, no data rules
src/app/backend/local-league-archive-backend.service.ts ADR 0028
src/app/backend/local-live-backend.service.ts           ADR 0021
src/app/backend/server-read-cache.service.ts            ADR 0031

Adding a fifth is an ADR decision, as it was for the fourth. Persistence in the cache service sits behind a ServerReadCacheStore seam, so the service is unit-testable with a fake and nothing else in the app grows an IDBDatabase parameter.
