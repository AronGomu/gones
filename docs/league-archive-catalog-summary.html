Slim League Archive Catalog

The list page printed two integers per card and paid 1.44 MB for them. Store the two integers. Ship 30 KB. The documents keep their own route, because the export genuinely needs them.

Where the two numbers come from

The card prints N tournaments · M players. N is document.Tournaments.Count. M is LeagueRules.CalculateLeagueResult(document).Rows.Count — the Swiss standings row count, which the browser was computing itself with calculateLeagueResult after downloading the whole document to do it. The backend already had the same function.

Why not the three obvious fixes

refused Compression alone

Gzips 1.44 MB to 103 KB. Still compresses a body that should never have been that size. Kept as an additional win, not as the fix.

refused Diff protocol

The catalog already has an ETag, a 304 and a 24 h browser copy (ADR 0039), so a repeat visit costs zero bytes. A diff only helps the first load — where a diff is a full load. A request body would also kill HTTP caching and need a client-side merge store.

refused Server-side paging

Breaks the client-side name filter and the union with browser-local Leagues (ADR 0028), and the paged summary rows carried no counts anyway. Paging stays in the browser.

Compression, narrowed

BREACH. Compressing an HTTPS response that carries a session secret alongside attacker-influenced input leaks the secret through the compressed length. So compression is enabled app-wide except for requests that carry credentials: a GET with no Authorization header and no session cookie is compressed; everything else is not. Every payload this document is about — the League catalog, the Event catalog, the rankings — is an anonymous public read.

app.UseWhen(
    context => HttpMethods.IsGet(context.Request.Method)
        && !context.Request.Headers.ContainsKey(HeaderNames.Authorization)
        && !context.Request.Cookies.ContainsKey(RefreshCookie.Name),
    branch => branch.UseResponseCompression());

Cache contract

Unchanged in shape, changed in content (ADR 0039).

localStorage key gones.leagues-archive.catalog.v2 — summary rows, 24 h TTL
legacy key gones.leagues-archive.catalog — held fat documents; cleared, never read
every League/Tournament mutation calls clearLeagueCatalogCache(), which drops both
~60 KB of UTF-16 instead of ~2.9 MB against a ~5 MB quota

Consequences worth remembering

  • The counts are denormalized, so they could disagree with the document. Three things stop it: they are written in the same domain call that writes the document, they are never editable on their own, and counts_version gates a self-healing repair.
  • Browser-local Leagues (ADR 0028) compute their own counts client-side, so the merged list is uniform and the local half never needs the server.
  • The export refuses to write a partial bundle: serverUnavailable() and catalogTruncated() both still block it. Those guards move to the documents route.
  • PublicLeagueCatalogApiTests' old assertion — a catalog item is byte-identical to the detail item — is gone by design.
