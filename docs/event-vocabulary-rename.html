Calendar Event Vocabulary

The calendar domain is renamed from Tournament to Event through every ring: domain types, PostgreSQL tables, API paths, frontend symbols and routes. The archived League domain, the Live domain and the shared format lookup keep their names.

Seven tables, five foreign-key columns, seven primary keys, eighteen foreign keys and thirty-two indexes are renamed in place by 20260812164333_RenameCalendarTournamentToEvent. scheduled_notifications and notification_history belong to the notification domain and keep their table names — only their FK column moves to event_id.

What is not renamed

shared tournament_formats

The format lookup (Modern, Legacy, …) is used by the archive domain too. Renaming it would widen the diff into a domain this decision does not touch.

separate League archive

leagues-archive / tournaments-archive already carry their own vocabulary from ADR 0022. Historical result tournaments stay tournaments.

separate Live tournaments

live-tournaments is the browser-run tournament (ADR 0021). A live tournament is genuinely a tournament, not an event.

Compatibility

API ─→ hard break. /api/tournaments/* returns 404. No aliases, per the ADR 0022 precedent.
Frontend routes ─→ permanent redirects, parameters preserved. Bookmarks keep working.
Browse page ─→ /calendar stays. The calendar is a view, not a namespace.
Wire shape ─→ unchanged apart from renamed fields; DTOs move from Tournament* to Event*, JSON tournamentId becomes eventId.
The migration is a rename, never a drop. EF scaffolds DropTable + CreateTable for an entity rename because the model snapshot still carries the old CLR name at diff time. Applying that scaffold would delete every event. The migration is hand-corrected into RenameTable, RenameColumn, RenameIndex and ALTER TABLE … RENAME CONSTRAINT, exactly like 20260809122735_RenameLeagueArchiveTables.cs.

Scope of the concept

An Event is today's record renamed. It is tied to a single tournament conceptually, and that tournament has no row of its own. Modelling an event as a container of several tournaments — with per-tournament capacity, formats and registration — is deferred to a later epic.

Commit order

1 ─ entities, tables, hand-corrected migration. HTTP surface untouched, OpenAPI byte-identical.
2 ─ endpoints, DTOs, error codes; OpenAPI and the generated Angular client regenerated.
3 ─ frontend services, components, types, data-cy values, Cypress specs.
4 ─ routes, redirects, breadcrumbs, i18n labels.

The frontend is knowingly mid-rename between commits 2 and 3; those two commits stay adjacent.
