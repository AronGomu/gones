Gones · Architecture

Player Rating — Glicko-2

One number per player, replayed from every rated Match in the server archive. It carries its own confidence, which is what answers the new player and the absent player without inventing rules. Stored, never exported. A restore recomputes it.

Why not match wins

The Global Rankings sorted by name, then match wins. That answers "who won the most matches", not "who is the best player": it rewards volume, ignores who you beat, and has no way to say how sure it is about anyone. Glicko-2 carries a deviation and a volatility alongside the rating, so a player with four results and a player with four hundred are ranked by the same formula without a special case.

The constraint that shaped everything: no clock

Archived Tournaments carry a date, not a timestamp. Matches inside a Round are unordered, and two Tournaments on the same date have no tiebreak. So a rating that needs a total order over matches cannot be built from this archive.

A rating period is one calendar date. Every completed Tournament on that date folds into a single period; every Match in it is evaluated against the ratings held before the period started. Match order inside a period therefore cannot change the result, and the missing timestamp stops being a problem. Periods replay in date order, ordinal on the ISO string.

Where the margin factor goes

The factor multiplies each Match's term in Δ and in the μ' sum. v — and therefore the new deviation — uses the unweighted terms, because v depends only on the opponents' deviations and the expected scores, never on the outcomes. That is what "the Glicko score term stays 1 / 0.5 / 0 so the deviation maths stays valid" means once it is written down.

g(φ)  = 1 / sqrt(1 + 3φ²/π²)
E(μ, μⱼ, φⱼ) = 1 / (1 + exp(-g(φⱼ)(μ - μⱼ)))

v = [ Σ g(φⱼ)² · Eⱼ · (1 - Eⱼ) ]⁻¹          ← unweighted
S = Σ fⱼ · g(φⱼ) · (sⱼ - Eⱼ)                ← fⱼ ∈ { 1.0, 1.25 }
Δ = v · S

σ' solved by Illinois regula falsi, τ = 0.5
φ* = sqrt(φ² + σ'²)
φ' = 1 / sqrt(1/φ*² + 1/v)
μ' = μ + φ'² · S

The engine is anchored by Glickman's own worked example: a (1500, 200, 0.06) player against (1400, 30) won, (1550, 100) lost, (1700, 300) lost, yields 1464.06 / 151.52 / 0.05999. That is a unit test, not a comment.

Default ranking order — three buckets

0 · active ranked
5+ Tournaments, played within 12 months. Ordered by rating, descending.
1 · inactive ranked
5+ Tournaments, nothing in 12 months. Rating frozen, deviation still growing. Badged, listed, never hidden. Ordered by rating.
2 · provisional
Fewer than 5 Tournaments. Rating shown, flagged not rankable. Ordered by tournaments played, then matches played.

Every tie breaks on the ordinal player name, ascending — Player Names are exact and case-sensitive (ADR 0040), so the tiebreak collates as C, not by browser locale.

Provisional players still move ranked ratings. Standard Glicko-2, no special case: their high deviation already damps the update. That damping is the reason Glicko-2 was chosen over Elo in the first place.

Both flags are derived at read time from tournamentsPlayed, lastPlayedDate and the request clock — never stored. Otherwise a player would go inactive at the next rebuild rather than on the day. The rankings ETag therefore carries the request date.

Decay — computed always, shown never (yet)

decayed = 1500 + (rating - 1500) × 0.5 ^ (idleMonths / 24)

Stored on every rebuild, served only when Gones:PlayerStatistics:ExposeDecayedRating is on — the Gones:PlayerStatistics:RebuildOnStartup precedent, default false. The column is already in the table, so flipping the key needs no rebuild. With the key off, the payload field is null and the frontend column simply does not render: the payload is the switch, there is no second frontend flag.

Surfaces

Global Rankings

Rating with its ±N since the player's own last period, a Tournaments column, provisional and inactive badges. Rating is the default sort. The four game columns left the table but stayed in the payload — they are still the tie-break.

Player page

Same rating and ±N, tournaments played, and the rating's state. With Online only off, the number does not move and a note says local Matches never affect it.

League standings

An informational, non-sorting Rating column. Swiss points still decide the order. A single Tournament's result table is unchanged — it passes no ratings map, so the column does not exist there.

Deliberately out of scope

  • Rating-driven pairing.
  • Archetype- or deck-level ratings.
  • Player identity unification. A rename changes the key; the replay produces the renamed player's rating and no merge logic is added.
  • A rating-over-time chart — it needs the history table this design deliberately skipped. Adding it later means adding the table, not changing this design.
  • Live Tournaments, until they land in the archive.
