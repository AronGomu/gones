Gones · Architecture

TTL Cache Contract

Site data changes once a day. Every page that reads the server loads once, keeps the copy 24 hours, and shows a Synchronize button. One contract, two stores — chosen by privacy, not by page. Private rows never touch localStorage and never outlive logout.

Why two stores

The Events page already worked this way (ADR 0023): whole catalog, localStorage, 24h TTL, ETag. The ask was to give every data page that same behaviour. Taken literally that puts registration lists, settings and admin user lists in localStorage — where they survive logout and the next account on the same browser can read them.

The right store already existed. ADR 0031 built a per-user IndexedDB cache with a cross-tab lock and a logout purge. Its contract, though, was fallback-only: a row was read only after the server read had already failed. It could not serve a fresh navigation. ADR 0039 amends that.

What every page shows

gones-sync-bar

One component, a caller-supplied cyPrefix so each page keeps stable test ids. Renders the "last synced" instant, the Synchronize button, and the offline banner.

The four states

  • fresh under 24h → served from cache, no request
  • expired over 24h → refetch, cache, render
  • forced Synchronize pressed → refetch regardless
  • stale request failed, row exists → render it, flag it

No row and a failed request is the only case that throws.

Catalog or per-query

"Cache like the Events page" has two meanings, because that page caches the whole catalog from /api/events/all and does its searching locally. That is why it feels instant. Server-paged endpoints cannot do that without a new endpoint.

A new public catalog endpoint copies /api/events/all exactly: cap 5000 rows (config-overridable), a truncated flag in the body, a SHA-256 ETag, and Cache-Control: public, max-age=3600. /api/leagues-archive/all caps at 1000 instead, because a League is a whole document of up to 1 MB rather than a fixed-width row.

Staleness is not allowed to lie

Mutation invalidates its own entry. An admin who grants a role must not then see the old role for up to a day. After a successful write the page calls invalidate(resource) — or invalidateFamily(family) when paging means many entries hold the same data — and refetches at once.

A rejected write leaves the cache untouched. The TTL governs navigation; it never governs correctness.

mutate() → await action() → throws? → cache untouched, error shown, done
mutate() → await action() → ok → invalidateFamily('admin-users') → reload({ force: true })

What the amendment does not change

unchanged Privacy

Rows are still keyed <userId>:<resource>. Every write still happens under withAvailableLock with the session scope re-checked afterwards, so a response landing after logout is answered to its caller and written nowhere. The purge registered with SessionScopeService still drops the whole database.

unchanged Fallback reads

read() keeps its ADR 0031 contract for every existing caller: a row is returned only after the server read has failed. readCached() is a second, additive entry point.

unchanged Authority

A cache is never an authority (ADR 0020). Nothing here is merged into a response, and nothing here is ever sent back to the server. indexedDB stays confined to the three files server-authority-boundary.test.ts allows.

Live Tournament. Only the list joins this contract. The runner does not, and the role-scoped adapter choice of ADR 0021 is untouched. When LocalLiveBackend is the selected adapter the read is already local IndexedDB, and readCached degrades to a pass-through for anonymous callers — so no branch is needed in the component.
