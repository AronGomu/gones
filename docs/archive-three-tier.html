Gones · Architecture

Three-Tier Archive

The Archive was one flat tier of League documents. It is now three rows in three tables — League → LeagueSeason → Tournament — and a Tournament is a first-class record that can stand alone with no parent at all. The browser keeps two IndexedDB databases, because an authority and a cache must never share a delete button.

The three tiers

Yesterday's flat League is today's LeagueSeason. A new League tier sits above it and groups Seasons; it has no page of its own, only a column and a filter. A Tournament used to live inside its League's document and now owns a row, a version and an id of its own.

The two parent links are deliberately asymmetric, and that asymmetry is the whole model:

Why no leagueId on a Tournament. Storing it would create a second path to the same fact, and the two paths would eventually disagree — move a Season to another League and every Tournament under it silently keeps the old one. One edge per parent link, and the League is a join. The cost is that Tab 2 must resolve a League name through the Season catalog it already holds; that catalog is in IndexedDB, so the join is local and free.

Every other column is projected so a catalog query never deserializes JSON — that is the point of ADR 0042 and it survives the rebuild intact. C# type names are Archive-prefixed throughout (ArchiveLeague, ArchiveLeagueSeason, ArchiveTournament in Gones.Domain.Archive) because a bare League collides with Gones.Domain.Leagues.LeagueArchiveAggregate and with the Live tournament. The TypeScript side keeps the unprefixed LeagueSeasonDocument, because its module has nothing to collide with.

Cache-Control is per surface, not uniform. Catalogs and the years index sit at an hour because they are bulk reads whose staleness the client already manages. Detail, result and rankings routes sit at 60 seconds, matching the legacy detail routes (PublicLeagueEndpoints.cs:20, private const string PublicCacheControl = "public, max-age=60"). An organizer's edit must not stay invisible in an HTTP cache for an hour.

year is required on /tournaments/all. Missing or non-integer is a 400. There is no "all years" mode — that is what the backfill queue is for. The 25000 ceiling comes from the measured mtgtop8 peak of roughly 17,500 tournaments in one calendar year, plus headroom, and follows the existing idiom: a Take(ceiling + 1) and a CapToCeiling that turns the extra row into the truncated flag (PublicLeagueEndpoints.cs:379-398).

What a summary row does not carry

absent locked

ArchiveTournamentSummary has no locked field. A row cached today as unlocked becomes locked tomorrow with no refetch to tell it, so the client derives the flag from tournamentDate. ArchiveYearEntry.locked is on the wire, because /api/archive/years is fetched every session and never cached across days.

absent rounds · playerArchetypes

A catalog row is not a document. The detail body is served by GET /api/archive/tournaments/{id} and is never written into a year partition — the partition holds fixed-width summary rows and stays small enough to keep 25,000 of them in a browser.

Tournament commands answer with the document. Restore is exempt from the lock because a bulk historical import mints new ids and rewrites no protected row. Gating it would make every backfill of pre-2025 data an Admin-only operation, which is the opposite of what the lock is for.

Two databases in the browser

An authority and a cache never share a database. The rule sounds abstract until you write the Settings button that empties the cache: with one database, "purge the cache" is one mistyped store name away from deleting records the user authored in this browser and that exist nowhere else.

Both names are constants, not string literals at call sites:

Year partitions and the single writer

The Tournament catalog is not one body. It is one body per calendar year, keyed by the year number, and a partition is written by exactly one component.

interface ArchiveYearPartition {
  year: number;
  completedAt: string | undefined;   // ABSENT ⇒ the year is not cached. Never write a partial one.
  rowCount: number;                  // the server's uncapped totalCount
  items: ArchiveTournamentSummary[];
}

invariant One writer

Only src/app/backend/archive-backfill-queue.ts writes the year-partitions store. Every other caller reads it. A second writer would need a cross-tab lock to stay coherent; one writer needs none.

invariant One transaction

The items and the completedAt stamp are written in a single IndexedDB transaction. A year is therefore atomically whole or absent — a crash mid-fetch leaves no record at all, never half of one, and no reader ever has to ask whether what it found is finished.

derived Truncation

There is no truncated field on the partition. rowCount holds the server's uncapped totalCount, so a cache-served year re-raises the row-cap warning by comparing items.length < rowCount. One fact, stored once.

enqueue(year) → GET /api/archive/tournaments/all?year=YYYY → one txn: put(items + completedAt)
fetch throws / tab closes → nothing was put → the year stays absent → re-enqueued next visit
drain(loader) walks the queue · restart() re-runs it from empty after a Settings resync

Expanding a Season row

Tab 1 expands one level, from a Season to its Tournaments. The expansion has to answer from the cache when it honestly can and go to the server when it cannot — and it must never write what it gets from the server into the cache, because a Season slice is not a partition.

A locked year is never refetched, and that is the deliberate trade: an Admin editing locked history is invisible to a browser that already has the year until someone asks for it. The escape hatch is the Resynchronize everything control in Settings, inside a collapsed-by-default section — it clears every cache store and re-runs the backfill queue. The staleness is accepted; the button is why it is acceptable.

One invalidation funnel. Every archive mutation goes through ArchiveRepository.invalidateArchiveCaches(): Promise<void>, which clears the gones-archive-cache stores and dispatches window.dispatchEvent(new CustomEvent('gones-archive-updated')). That renames today's gones-league-updated event, dispatched from the legacy archive detail components and listened for in src/app/app.component.ts. A coverage test asserts every mutating method on the repository calls it — the invalidation worked before, but nothing proved it stayed wired.

The 365-day lock

A Tournament stops accepting non-Admin writes 365 days after the day it was played. The rule is derived, never stored: there is no locked column, no lockedAt timestamp and no job that flips a flag at midnight.

export const ARCHIVE_LOCK_WINDOW_DAYS = 365;
export function isArchiveTournamentLocked(tournamentDate: string, now = new Date()): boolean;

// C# mirror
public static class ArchiveLockRule {
    public const int LockWindowDays = 365;
    public static bool IsLocked(LocalDate tournamentDate, LocalDate today);
}

The boundary, exactly

locked ⇔ (now − tournamentDate) > 365 days, compared on whole UTC calendar days. Played exactly 365 days ago: not locked. 366 days ago: locked. Both stacks implement the same comparison so a client that hides the edit button and a server that rejects the write never disagree by a day.

Browser-local records never lock

A record with a local- id prefix lives only in this browser and has no server to protect it from. Locking it would take a user's own data away from them for no benefit.

The 🔒 marker is visible

Locked rows carry the marker in the table, not just in a rejected save. A Season is locked when every one of its Tournaments is locked — an unlocked child means the Season still accepts work.

Concurrency and the denormalized counters

Concurrency is per Tournament. Each row guards itself with its own documentVersion. Editing a Tournament does not bump its Season's version, and does not bump its League's — two organizers editing two Tournaments in the same Season never collide, which is precisely why Tournament became a row instead of an array element.

Archive rows do not derive VersionedEntity, and that is load-bearing. The key is document_id text PRIMARY KEY with a plain version integer mapped .IsConcurrencyToken() — the precedent is PlayerStatisticsRow, which does not derive it either. GonesDbContext.IncrementVersions (GonesDbContext.cs:78-85) only auto-bumps entries it can walk as ChangeTracker.Entries<VersionedEntity>(), so every archive row write must increment version explicitly. Forgetting it does not fail loudly; it silently disables optimistic concurrency for that path.

On the wire, documentVersion is an int, not a long.

The Season carries four denormalized counters — tournamentCount, playerCount, firstTournamentDate, lastTournamentDate — plus a counts_version. They are recomputed inside the same transaction as the Tournament write that changed them, exactly as ADR 0042 already does for TournamentCount / PlayerCount / CountsVersion on LeagueArchiveAggregate (see RefreshCatalogCounts() at backend/src/Gones.Domain/Leagues/LeagueArchiveAggregate.cs:129-135).

PATCH a Tournament → validate lock → check documentVersion → write row (version + 1)
… same transaction → recompute the parent Season's four counters + counts_version
version mismatch → 412 stale_version → nothing written, counters untouched
tournamentDate older than 365 d, actor is not Admin → 409 archive_tournament_locked

Three things keep a denormalized counter honest, and they are the same three ADR 0042 relies on: it is written by the domain call that writes the row, it is never editable on its own, and counts_version gates a self-healing repair for the case a formula changes under existing rows.

Consequences worth stating out loud

  • The League tier is our own construct. Public archives expose no series or season field — a real mtgtop8 event record carries title, venue, format, star rating, player count, date and decklists, and nothing else. So LeagueSeason.name is a free string with no integer-year column: calendar years are the common case, but Pro Tour 1996–2012 ran August-to-August seasons named 1996–97, and a stored year would have to lie about them.
  • A standalone Tournament has no League name to print. Tab 2's second line is empty for it — not Unassigned, not a placeholder row. The retired PLACEHOLDER_LEAGUE_ID / Unassigned Tournaments pair existed only because the old model had nowhere else to put a parentless Tournament.
  • Two surfaces, two page-size defaults, both deliberate. The archive tabs default to size=25 (choices 25 | 50 | 100); the rankings keep their existing pageSize=100.
  • Every read route is anonymous. Nothing in this document is behind a session, so the whole archive is readable offline once cached, and the ADR 0042 compression rule applies to all of it.
  • The sort-direction URL parameter is dir everywhere — archive tabs and /global-stats alike. The wire query parameter sent to the API stays direction, which is what PublicLeagueEndpoints binds today. The rankings page currently writes direction= into its own URL (src/app/features/players/global-stats-query.ts:196, asserted at cypress/e2e/global-stats.cy.js:76-78); that is a user-visible URL change to an existing page, accepted because Gones is unreleased and has no users.

Bounded by ADR 0020 (a cache is never an authority), 0028 (browser-local archive authority), 0037 (staged edits), 0039 (TTL cache contract) and 0042 (slim catalog rows, denormalized counters, narrowed compression). Supersedes the flat model of 0022.
