Gones · Architecture

Calendar Data Flow

One request a day fetches every present-and-future tournament. Everything the user types after that filters a local array. The month grid never disappears.

Before and after

Was

  • Six filter inputs + an Appliquer button
  • Each apply = a router navigation + a paged request
  • Server-side WHERE per field, exact match
  • Month change = another request
  • Zero results = no calendar at all

Is

  • One search input, full page width
  • One request per 24 h, plus a manual Synchroniser
  • Client-side fuzzy match across every field but the description
  • Month change = zero network
  • Zero results = the grid renders, empty, with a notice below it

The read pipeline

PublicCalendarComponent — searchDraft(), month, view signals
filterTournaments(allItems(), q) — fuse.js over normalized text pure
AllTournamentsCacheService.load() 24 h TTL
localStorage gones.calendar-v1.all-tournaments — items + etag + fetchedAt
GET /api/tournaments/all?from=… — If-None-Match only on miss / force
PostgreSQL scheduled_tournaments ⋈ organizations

Search-term grammar

Separators are ,, ; and whitespace. A backslash escapes the next character, so a separator can be part of a term. Terms are ANDed.

InputTermsMatches
lyon['lyon']anything in Lyon
lyon, legacy['lyon','legacy']Legacy events in Lyon
saint\,étienne['saint,étienne']the literal string, comma included
grand\ prix['grand prix']the phrase, not two words
RHONE['rhone']matches Rhône — accents and case folded
2026-09-12['2026-09-12']that venue date

Searchable corpus

title · slug · status · organization.name · formats[].name
venue.streetAddress · venue.postalCode · venue.city · venue.country
timeZoneId · venueStartDate · venueStartTime · venueEndDate · venueEndTime · capacity

EXCLUDED: summary / description  ← long free text, deliberately not searched

The bulk endpoint

GET /api/tournaments/all?from=2026-08-08          # anonymous

200 OK
ETag: "9f2c…"                                     # sha256(count : maxUpdatedAt : lastId)
Cache-Control: public, max-age=3600
{
  "items":       [ …PublicTournamentSummaryResponse… ],
  "generatedAt": "2026-08-08T09:14:02Z",
  "count":       137,
  "truncated":   false
}

304 Not Modified                                  # when If-None-Match matches
Ceiling, not a cliff. Gones:Calendar:MaximumCatalogSize defaults to 5000. Past it the response is capped, truncated flips to true, the server logs a warning and the page renders a visible notice. Silent truncation would read as "you have seen everything" when you have not.

Page layout — what the pipeline feeds

The catalogue above is one fetch. The page then splits it across two tabs that consume it very differently. Document order on /calendar:

[ back to menu ]                          [ synchronised 12:04 ] [ ⟳ Synchronise ]
Public tournaments                                              [ Create tournament ]
<search input — no label, no border, no background>
[ Calendar ] [ List ]
────────────────────────────────────────────────────────────────────────────────
calendar tab                              │  list tab
  [ Previous ]      August 2026   [ Next ]│    venue-date group headings
  ┌─────┬─────┬─────┬─────┬─────┬─────┐   │    tournament cards, 20 per page
  │  1  │  2  │  3  │  4  │  5  │  6  │   │    [ Previous ]  Page 1 of 3  [ Next ]
  └─────┴─────┴─────┴─────┴─────┴─────┘   │
The month grid holds day numbers and nothing else. Tournament entries were removed from the day cells deliberately: the calendar tab is a date surface, the list tab is the discovery surface. buildMonthDays(month) therefore takes only a month and no longer depends on the filtered set, so typing in the search box does not re-render the grid.

What the filter still drives

searchDraft() → filterTournaments(allItems(), q) → items()
items() → empty-state panel both tabs
items() → sortTournamentsForList() → paginateTournaments(…, page) → groups() list tab
the month grid reads none of the above — only query().month

The search text is debounced 300 ms into the q query parameter. Changing q, month or view resets page to 1; page 1 is never written to the URL, so a shared link stays clean.

Pagination

SymbolWhereRule
PAGE_SIZEpublic-calendar.ts20
sortTournamentsForListsamevenue date, then start time, then title, then id — a stable flat order is what makes paging deterministic
calendarPageCountsamemax(1, ceil(total / 20)) — an empty list is still one page
clampCalendarPagesameout-of-range, fractional and NaN pages resolve to a real page
paginateTournamentssameslices after clamping, so a hand-edited URL never renders an empty list

Grouping happens after paging: the 20 tournaments of the current page are then split into venue-date sections. Paging by group would give pages of wildly different sizes.

Boundary rules this respects

  • Read-only. Nothing here writes; publication still goes through the organizer endpoints or the proposal flow.
  • Filtering, sorting and paging are pure functions over the cached snapshot. No request is issued by typing, by turning a page or by changing month — only Synchronise and a cache miss reach the network.
  • localStorage holds a cache of anonymous GET responses and nothing else — the same justification the pre-existing entries in the server-authority-boundary.test.ts allowlist carry. It is never a mutation source.
  • The paged GET /api/tournaments stays, contract-tested. It is the documented public read API; this application simply no longer calls it.
